## Invarianti del reducer (fonte di verità per tutti i task)

Stato del run (NewRay.md §8.3): `queued → running → completed`, con ramificazioni `waiting_approval → queued/running`, `failed`, `cancelled`, `interrupted`. Terminali: `completed`, `failed`, `cancelled`, `interrupted`.

Regole del reducer puro (deterministiche):
1. **Dedup:** un evento con `sequence <= lastSequence` già applicato è un no-op.
2. **Fuori-ordine già visto:** stesso effetto del dedup (no-op).
3. **Buco:** `sequence > lastSequence + 1` → NON appendare (sarebbe riordino/raddoppio); segnala `needsSnapshot` per riconciliazione autorevole.
4. **Terminale unico:** una volta `terminal !== null`, ogni evento non terminale è ignorato.
5. **Riconciliazione snapshot:** lo snapshot sostituisce `text` con il valore autorevole e resetta `lastSequence` → nessun raddoppio di testo.
6. **Output parziale:** su `cancelled`/`interrupted` il `text` accumulato resta visibile (non viene azzerato).
7. **Modello:** la view mostra sempre `view.model` (dallo snapshot del run), mai un selettore live.

```ts
import type {
  ConnectionStatus,
  RunEventEnvelope,
  RunSnapshot,
  RunState,
  RunView,
  TerminalDetail,
} from "./types";

export type RunAction =
  | { type: "reset"; runId: string }
  | { type: "connection"; connection: ConnectionStatus }
  | { type: "stopRequested" }
  | { type: "snapshot"; snapshot: RunSnapshot }
  | { type: "event"; event: RunEventEnvelope };

export function createRunView(runId: string): RunView {
  return {
    runId,
    state: "queued",
    model: null,
    text: "",
    truncated: false,
    terminal: null,
    stopRequested: false,
    connection: "connecting",
    lastSequence: 0,
    needsSnapshot: false,
    tools: [],
  };
}

function terminalFor(state: RunState): TerminalDetail | null {
  switch (state) {
    case "completed":
      return { kind: "completed" };
    case "failed":
      return { kind: "failed" };
    case "cancelled":
      return { kind: "cancelled" };
    case "interrupted":
      return { kind: "interrupted" };
    default:
      return null;
  }
}

function applySnapshot(view: RunView, s: RunSnapshot): RunView {
  return {
    ...view,
    state: s.state,
    model: s.model,
    text: s.output.text,
    truncated: s.output.truncated,
    terminal: terminalFor(s.state),
    lastSequence: s.last_sequence,
    needsSnapshot: false,
  };
}

function applyEvent(view: RunView, e: RunEventEnvelope): RunView {
  // Terminale unico: una volta terminato, ogni evento non terminale è ignorato.
  if (view.terminal !== null) return view;
  // Dedup / fuori-ordine già visto: no-op.
  if (e.sequence <= view.lastSequence) return view;
  // Buco: non appendare (riordino/raddoppio); chiedi snapshot autorevole.
  if (e.sequence > view.lastSequence + 1) return { ...view, needsSnapshot: true };

  // Contiguo: e.sequence === view.lastSequence + 1.
  const next: RunView = { ...view, lastSequence: e.sequence };
  switch (e.type) {
    case "run.queued":
      next.state = "queued";
      break;
    case "run.started":
      next.state = "running";
      break;
    case "run.waiting_approval":
      next.state = "waiting_approval";
      break;
    case "message.delta":
      next.text = view.text + (e.payload.text as string);
      break;
    case "tool.started":
      next.tools = [...view.tools, { id: e.payload.tool_id as string, state: "started" }];
      break;
    case "tool.completed":
      next.tools = view.tools.map((t) =>
        t.id === (e.payload.tool_id as string) ? { ...t, state: "completed" } : t
      );
      break;
    case "sources.updated":
    case "artifact.updated":
      // Nessuna variazione di vista in questa slice (B-08.7).
      break;
    case "run.completed":
      next.state = "completed";
      next.terminal = { kind: "completed" };
      break;
    case "run.failed":
      next.state = "failed";
      next.terminal = { kind: "failed", code: e.payload.code as string, message: e.payload.message as string };
      break;
    case "run.cancelled":
      next.state = "cancelled";
      next.terminal = { kind: "cancelled", code: e.payload.code as string, message: e.payload.message as string };
      break;
    case "run.interrupted":
      next.state = "interrupted";
      next.terminal = { kind: "interrupted", code: e.payload.code as string, message: e.payload.message as string };
      break;
  }
  return next;
}

export function runReducer(view: RunView, action: RunAction): RunView {
  switch (action.type) {
    case "reset":
      return createRunView(action.runId);
    case "connection":
      return { ...view, connection: action.connection };
    case "stopRequested":
      return { ...view, stopRequested: true };
    case "snapshot":
      return applySnapshot(view, action.snapshot);
    case "event":
      return applyEvent(view, action.event);
  }
}
```

### Task 4: Client SSE (fetch + parser)

**Produces:**

**Inputs / References:**

- [ ] **Step 1: Definire l'interfaccia**

`openEventStream` è un generatore asincrono che:
- Fa `fetch(url, { signal, credentials: "same-origin" })`.
- Se `!res.ok` o `!res.body` → getta `ApiError` (stato, codice dal corpo JSON se presente, altrimenti `INTERNAL`).
- Legge `res.body` con `getReader()`, decodifica con `TextDecoder`, accumula in buffer.
- Separa i frame SSE sul delimitatore `\n\n`; per ogni frame raccoglie le righe `data:` (giunte con `\n`), e se non vuoto `yield JSON.parse(data)` come `RunEventEnvelope`.
- Rispetta `signal` (abort → il generatore termina; `reader.read()` getta `AbortError`).

- [ ] **Step 2: Implementare**

Creare `web/src/shared/api/sse.ts`:

```ts
import { ApiError } from "./client";
import type { RunEventEnvelope } from "@/features/run/types";

/**
 * Client SSE minimale su fetch + ReadableStream (NewRay.md §19.3).
 * Non usa EventSource: serve il replay parametrico (`after_sequence`),
 * l'abort esplicito e i cookie same-origin senza CORS.
 */
export async function* openEventStream(
  url: string,
  signal: AbortSignal
): AsyncGenerator<RunEventEnvelope, void, unknown> {
  const res = await fetch(url, { signal, credentials: "same-origin" });
  if (!res.ok || !res.body) {
    let code = "INTERNAL";
    try {
      const body = (await res.json()) as { code?: string };
      if (body.code) code = body.code;
    } catch {
      // corpo non JSON: codice stabile di fallback
    }
    throw new ApiError(res.status, code, "stream non disponibile", true, "");
  }
  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = "";
  try {
    for (;;) {
      const { done, value } = await reader.read();
      if (done) break;
      buffer += decoder.decode(value, { stream: true });
      let idx: number;
      while ((idx = buffer.indexOf("\n\n")) !== -1) {
        const frame = buffer.slice(0, idx);
        buffer = buffer.slice(idx + 2);
        const data = sseData(frame);
        if (data) yield JSON.parse(data) as RunEventEnvelope;
      }
    }
  } finally {
    reader.releaseLock();
  }
}

function sseData(frame: string): string | null {
  const lines = frame.split("\n");
  const dataLines = lines.filter((l) => l.startsWith("data:")).map((l) => l.slice(5).replace(/^ /, ""));
  if (dataLines.length === 0) return null;
  return dataLines.join("\n");
}
```

### Task 6: Hook `useRunStream`

**Produces:**
- `web/src/features/run/useRunStream.ts`

**Inputs / References:**
- `web/src/features/run/reducer.ts`, `types.ts` (Task 1-2).
- `web/src/shared/api/sse.ts` (Task 4).
- `web/src/shared/api/client.ts` (`apiFetch`).

- [ ] **Step 1: Definire il comportamento**

`useRunStream(runId: string)` restituisce `{ view, retry }` dove `view` è lo stato del reducer.

Comportamento:
- **Init:** `connection: "connecting"`; fetch `GET /runs/{id}` (snapshot) → dispatch `snapshot`; poi apre lo stream.
- **Stream:** `openEventStream(/runs/{id}/events?after_sequence={confirmed}, signal)`. Per ogni evento: dispatch `event`. Se `event.sequence === confirmed + 1` → `confirmed = event.sequence` (cursore confermato).
- **Riconciliazione:** se dopo un dispatch `view.needsSnapshot` è true → fetch snapshot → dispatch `snapshot` → riapre lo stream da `snapshot.last_sequence`.
- **Riconnessione:** se lo stream termina/errore e il run non è terminale → `connection: "reconnecting"`, backoff (500ms, 1s, 2s, max 5s) e riapre dal `confirmed`. Se terminale → `connection: "closed"`, stop.
- **Unmount:** abort dello stream (chiude lo stream browser, NON cancella il run).
- **`retry`:** riavvia il ciclo init (per l'errore di snapshot iniziale).

Implementazione con `useReducer(runReducer, runId, createRunView)`, un `AbortController` in ref, `confirmed` in ref, e un `useEffect` su `runId` che orchestra init/stream/reconnect con un flag `cancelled` locale per evitare race su unmount.

Scrivere `useRunStream.ts` rispettando il comportamento sopra. Note:

- Su errore snapshot iniziale: `connection: "closed"` + esporre `retry` (non retry cieco, NewRay.md §19.4).

### Task 12: Spec e2e run (guasti deterministici in browser)

**Produces:**
- `web/e2e/ui/run.spec.ts`

**Inputs / References:**

- Criteri di accettazione B-08.6: disconnessione a metà risposta, due tab, replay, stop in coda/inference, click ripetuti convergono al transcript server.

- [ ] **Step 1: Definire i test**

Test (ognuno carica `/dev/run/run_1` con lo scenario run mockato):
1. **Replay contiguo:** eventi `queued→started→delta×3→completed` → la view mostra il testo completo e lo stato `Completata`; nessun raddoppio.
2. **Disconnessione a metà risposta + riconnessione:** `dropAfter` a metà dei delta → la view passa a `Riconnessione…`, poi riprende dal cursore e converge al transcript server completo senza raddoppiare il testo già ricevuto.
3. **Buco → riconciliazione snapshot:** `gap` che salta un sequence → la view recupera lo snapshot autorevole e il testo finale coincide con quello server (nessun raddoppio).
4. **Stop in inference:** click `Arresta` → appare `Arresto richiesto`; il mock emette `run.cancelled` → la view passa ad `Annullata` con l'output parziale conservato.
5. **Click ripetuti su Stop:** N click rapidi → un solo `POST /runs/{id}/cancel` (contare le richieste nel mock) → converge ad `Annullata`.
6. **Due tab:** due `page` sullo stesso run, entrambi replay dal cursore → entrambi convergono allo stesso transcript server (testo identico, nessun raddoppio).
7. **Refresh:** `page.reload()` → la view riletta da snapshot + replay converge al transcript server.
8. **Modello dallo snapshot:** la view mostra `model_name` dello snapshot, non un valore diverso.
9. **Navigazione chiude lo stream (non il run):** da `/dev/run/run_1` si naviga a `/conversations` → la route SSE viene abortata (verificare che il mock non riceva più chunk / la connessione chiuda) e nessun `POST /runs/{id}/cancel` viene inviato. Tornando a `/dev/run/run_1` la view recupera da snapshot + replay.
10. **Logout chiude lo stream e pulisce i dati privati:** da `/dev/run/run_1` si revoca la sessione (revoke ok) → la route SSE viene abortata, la view smonta, e dopo il redirect a `/login` nessun dato del run resta visibile (nessun `POST /runs/{id}/cancel`, nessun raddoppio).
